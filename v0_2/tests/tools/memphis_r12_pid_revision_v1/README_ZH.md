## 本轮交付与边界

1. 编制 JSON：设备/模板、端口、显式连接、设计要求、来源、修订、未决事项和绘图坐标分别登记。
2. 展开 JSON：保留原源侧/罐功能路径，展开 G01 的6台CDU、12台二次泵、18柜及72个机柜选择阀；新增管段与设备内部通道分别登记。
3. SVG与离线查看器：默认显示 C01B 和第一柜，可在同一组的6台CDU/18柜间选择，支持缩放和当前SVG下载。图纸并不假装显示实际运行状态。
4. 数据校验：文件身份、位号唯一、端口完整、介质隔离、数量、二次无泵/过滤/HX旁通、过滤器两端隔离等。是小规模文档结构检查，不是热水力、控制器或压力测试。

原 R12、原35项静态证据与冻结 M1 均不修改。原功能图内源侧/负荷泵组仍是原抽象；没有据此证明全厂设备明细完备。本次详图范围仅 PID-005 / PID-006 接口，不是全套施工 P&ID。

## 歧义如何消除

新版不画穿越二次泵和过滤器的中心贯通线；二次唯一合法流程是回液隔离→一条泵支路→一条过滤支路→板换→供液隔离。每台泵的入口隔离、泵、止回、出口隔离全部展开。

二次过滤器隔离阀的具体位号/布置为本次设计修订，橙色标识。一次侧原“过滤器/旁通厂家定”也不再画成模糊连接：提出两路均经过过滤、各有入口/出口隔离的方案，单路110m³/h是**新增拟定要求**，不是厂家保证性能。源文档只确定一次≤500μm；不能说原图已经批准每路100%配置。

CDU身份、一次网、二次网独立。CDU B可选择一次A；这不接通一次B，也不表示B罐放冷。供回必须同网成对。机柜A/B短时重叠须另经联锁许可；图中两路同时画出，不等于两路同时开启。

只有共同端口ID定义流体连接；交叉无实心节点不连通。板换只存在一次、二次各自的液路和独立热耦合，禁止混液边。虚线仅为仪表取样/信号，不参与流体图。仪表标签可省略公共设备前缀，完整位号在SVG悬停标题和JSON中。

## 生成方法

在此目录执行 `node build.mjs [输出目录]`。该命令仅处理文件、展开文档拓扑并绘图；不加载模型、不运行Python、不调用真实设备。

查看 `pid_viewer.html`；SHA256见 `package_manifest.json`。原功能图副本按 `pid_spec.json` 中SHA256验证；副本路径为 `inputs/R12_EXECUTABLE_TOPOLOGY.original.json`。

后续仿真适配器应消费本次展开 JSON，并另行绑定实际物理参数与已释放测量。**图纸流程明确，不等于已经证明流量、温度或接管成功。**
