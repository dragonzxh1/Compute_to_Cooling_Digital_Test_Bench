# 孟菲斯失败闭环 V1 — 开发执行入口

仅在 `codex/memphis-failure-closure-v1` 分支推送版本化源码，GitHub Actions
自动运行一次有界开发 campaign。禁止本机 Python/native/model 执行；不需要
且不得运行正式 C3-C。每个实际 Python 子进程须先获外部 Job 身份证明和
release，CPU25%、1024/2048MiB、480秒；每阶段结束记录cleanup0。

`registration.json` 固定40阶段与有限参数；`scenarios.py` 展开新场景身份；
`prior.py` 对原官方ZIP、每个raw文件、34个场景及两组各5失败独立追溯。
`checks.py` 复算物理守恒、Q-H、测量Ready和M1四阶段因果；工程不通过
仍保留实际结果，不作为软件执行异常抹去。`report.py` 汇集全部阶段后
交付中文报告、实际曲线及厂家RFI/FAT/SAT待确认规格。

A–E为受控研究配置：A原数量/85%冷库存；B加预冷/85%；C预冷/90%；
D再加源能力15%/速度3%裕量/备用泵/独立快测链；E再加独立W3接口及20m³。
所有新增回路、设备和合成曲线均是待OEM证明的工程提案，不是00/01既有事实。
最终采购候选A/B/C在报告中另行映射，不能和研究配置混用。

Build004的W2/W3预冷从48.29°C暖管实际起算；停预冷泵后环境热增益仍
持续，单独执行7200s保持试验，区分“温度仍冷”和“有流量证明的Ready”。
故障后回充试验验证A库存保守证明后回到3运行1备用；另加两个孤立单泵
退出对照，保留原接管过程二次泵故障案例，不把不同故障基准混成同一项。

Build005另外注册源侧40s完全停止发布样本的负面场景。项目源侧保护每
200ms重新检验已发布样本的时间有效性；这不产生新测量、不增加M1样本
信用、不读取模型hidden状态。完全失联后必须锁存SOURCE_SENSOR_STALE并
进入PROTECTED_HOLD、停止源泵许可；迟到新样本不能自动清故障。

温度45°C、负荷/源330m³/h、90秒窗口及罐出口升温0.5K均不放宽。
安全拒绝、热、水力、源恢复、储备恢复分开判。OEM无签章，采购与工程批准
持续阻塞；新增预冷隔离阀的动态、共因供电和完整现场拓扑仍需集成FAT/SAT。
