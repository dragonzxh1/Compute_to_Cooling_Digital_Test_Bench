# C3-C infrastructure v1 — development preparation only

This new namespace implements exact-byte user-approval and execution admission,
source/input closure verification, exact environment checks and distinct
PASS/FAIL/INCOMPLETE/INVALID adjudication. It does not reuse a development PASS as
formal qualification or alter sealed candidate/guard/comparator/fixture bytes.

The current preflight runs 31 synthetic unit tests, with no candidate/reference
imports, in an independently verified GitHub Python Job. It never creates a user
approval receipt or executes C3-C behavior. No final executable package exists yet.
The future behavioral runner, evidence schema, exact stage inventory and user
signable package remain required; this module alone cannot authorize execution.

Frozen input metadata must match the original C3-A input inventory, and all four
scope/SEM01/SEM02/PF06 registration files must be separately byte bound. The old
49/50 and five causal exclusions remain explicit; complete-only publication is
mandatory. Arbitrary exception atomicity, T09/hardware/fullP remain unproven.

Only use the hash-bound `m1-c3c-preflight.yml` on the dedicated source branch.
Do not run local Python/native/model tests on the hard-hanging workstation.
Synthetic approval objects used by unit tests are not real approval artifacts.
