## 启动与三分钟演示

在仓库根目录运行（标准库网页服务，不加载数值模型）：

```powershell
& 'D:/Github/c2c-itq-qualification-r3/Scripts/python.exe' -B -m v0_2.tests.tools.engineering_design_mvp_v1.server --port 8768
```

1. 在设计总览查看 18×155×0.95 = 2650.50 kW；点击一项检查，在右侧查看原因、公式、参数来源及修改风险。
2. 把每罐容积15改为20m³，比较阈值冷库存估计10.5→14m³；90秒出口仍保持“数据不足”，不会自动变绿。
3. 把UA220改为110kW/K，观察条件性换热能力及要求变化；未知Q-H、NPSH和真实定压仍为空。
4. 在P&ID页创建 RETURN→SUPPLY 的研究 pipe，程序定位绕泵、过滤器、HX路径。删除后重新检查，修改记录保留，基线不覆盖。

### 图形工作台升级（2026-10-24）

默认入口现在是2D设备画布，工程检查、端口编辑和方案比较仍然保留。参考阿拉木图交互P&ID的“场景预设、设备热点、管路流动覆盖层与数值同步”方式，没有采用其阿拉木图参数、消防/燃油模型或浏览器即时求解器。

1. 数据来源选“历史单柜”，在正常、阶跃、静默卡泵、测量丢失、一次边界升温五项已保存试验间切换。游标保持相同时间，设备温度、泵反馈、流量、故障与曲线同步更新。它们来自旧run39010789593，不是当前设计新计算。
2. 播放/暂停、逐帧、倍速、时间滑块与事件定位共享游标。默认隐藏未来；模型真值与已到达观测独立。测量失效不补零、不继续显示已知流动；命令不代替泵反馈。图上单击看详情，双击设备下钻；放大后可拖动，键盘方向键平移、Home复位。
3. 当前设计支持系统功能总览、六柜分组及CDU端口图。端口线直接读取JSON；完整施工管路未展开的部分用功能关联或空白表示，不猜测A/B选网，不把CDU B绑定到一次B。参数编辑后图上设计容积和工程检查更新，新动态结果仍需独立计算。
4. A/B历史回放读取旧V2各20层的真实记录。低温阈值体积、参考显热与90秒放冷资格不混称SOC。没有逐段流量与实际阀位的冷源/储罐关联，不绘制活动切换流路。
5. “导出此图与回放”产生自包含HTML，保留当前场景、游标、真实数据与图例；离线可播放但不能修改原方案、操作设备或提交任务。它与“方案比较”中的静态工程决策报告分别导出。

管路流带速度只单调表达相对流量，不是流体质点、m/s或输送延迟。流带按逐帧位移累计，流量变化不重新摆位；暂停保持当前位置，减少动态偏好下只显示静态方向。节点温度使用固定35–55°C色标（超出范围饱和），不虚构管内空间温度。泵的故障标记仅显示原跟踪故障确认；测量不足不会被误标为泵已损坏。

分层罐旁直接标注层号与温度（两位小数），20层回放逐层显示；选择某层后右侧提供完整温度表、对应层高亮及原始数值。80/160层等密网格仍显示全部真实层块，图上抽稀文字避免重叠，右侧列表保留每层。显示小数位数不代表实际测量精度或已完成标定。

本轮没有新增数值试验。当前版本的新动态结果仍待授权的远程执行；既有完整18柜/施工P&ID联动、任意阀门故障即时重算与新拓扑动态适配均未完成。

## 数据与来源

- `data/baseline.json`：00/01 B020/B146/B154/B163功能与设计预算；文件定位是DOCX顶层B编号，不是印刷页码。`sources`保留原件和既有依据哈希。rho/cp、UA、气象初值与分层初态明确为研究假设。
- `data/historical.json`：真实层温和曲线的只读投影；生成时对照原始artifact索引哈希核验。浏览器加载时再核验服务提供的文件哈希。不把历史工程FAIL改写成当前PASS。
- `data/single_history.json`：5项单柜原始JSON的只读转码；`prepare_visual_data.ps1`先核验官方artifact身份及ZIP摘要，再提取4类原件并登记各自原始SHA256。未覆盖或修改旧HTML/模型。回放不是原文件逐字节副本，绑定的是ZIP内原始条目。
- `data/parameter_contract.json`：前后端共享的单位与有界输入；未知不填零，厂家确认值需绑定工况及证据。
- `source_manifest.json`：新代码与未修改旧模块文件身份；不包括可变请求本身。请求原始哈希、设计规范JSON哈希和执行commit另行绑定。
- `data/baseline_report.html`：可离线打开的初始决策报告，包含静态矩阵及明确标识的旧研究回放数据。

## 动态能力清单

独立罐适配器复用既有守恒通量方程，容积、密度、比热、初始冷/热温度、冷液比例及混合为有界输入。A/B是相同初态的两个独立组件展示，不是完整切换试验。报告80/160层各自出口温升与能量残差；不按有利网格挑选PASS。流量是边界，不是泵已建流证明。未计壁面散热、真实布水器及外部泵热。

六柜适配器只复用既有 `RackLoop`，不改原求解器/M1。逐柜支路求流量与回液温度，公共供液节点是明确约简假设；固定一次入口/流量、给定泵速，泵电功入液一次。支持当前UA、物性、负荷、路径阻力与研究泵参数；入液比例非0.95或拓扑被修改时拒绝，不能默默忽略。未填写泵曲线时沿用登记的未标定研究曲线并在结果中标识，不作为OEM性能。

## 远程运行与安全

新工作流 `.github/workflows/engineering-design-mvp-v1.yml` 只接受新专用分支。每个任务只跑一个登记模型，90或60秒物理时间；CPU允许全部分配容量，进程4GiB/Job8GiB，480秒单任务硬上限。超时不自动扩预算、不分段、不重跑。

本地服务不接受命令、模型文件路径或浏览器传入源码commit。由可信操作者通过 `--remote-config` 配置固定源码commit和授权开关，凭据只由本机GitHub CLI持有。每次提交仅创建数据请求的新分支，原源码固定；同输入同模型复用已有任务，不重复发起。

结果接收检查官方ZIP摘要、逐文件原始索引、commit/manifest/request/design身份、实际Python Job、执行前后环境、资源及清理；绿色Actions不是工程PASS。远程接口与数值适配尚待本轮授权后的实际验证，不能以本地静态测试代替。
